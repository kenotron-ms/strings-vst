# Listening-first image studies: design review

November 7, 2026. Expert inspection of GPT Image concepts, not a musician study
or a test of implemented audio/UI behavior. These supplement, not replace, the
five earlier Astra interactive workflow studies.

Subsequent user clarification supersedes the staff notation in these images:
use the compact note ribbon in `sound-first-direction.md`. Sound quality and
assisted performance take priority over score display or teaching violin motion.

## Recommended product flow

Use **Listen as the front door**, **Refine as the composer's revision workspace**,
and **Shape as an optional explanation of the sound**. Perform is a focused
device-learning flow; Model is an expert drawer. No controller purchase or
violin technique should be required just to audition and compare a phrase.

| Concept | What works | What still needs production design |
| --- | --- | --- |
| Listen | One obvious audition action, a repeatable phrase, character and A/B without a permanent setup desk. The selected v2 fixes axis pairs and makes input selection available. | The model changed bottom navigation despite the preservation instruction: Refine must be restored in a production layout. Musical notation should also offer a simple note-ribbon alternative. The output meter is illustrative, not live telemetry. |
| Shape | A drawer makes physical controls discoverable while keeping audition/compare available. Contact gets a useful bridge/fingerboard explanation. | Normalize character axes with Listen. Replace overly certain “more warmth/life” or brightness promises with calibrated recipes; extreme physical controls need not change sound monotonically. Restore one shared header/navigation component. |
| Perform | One highlighted R2 lesson, independently mapped motion/touch/pitch, capability checks rather than a connected claim, feedback off and release available. | Explicitly teach “hold L2 to engage, release to lift”; a Lift label alone is ambiguous. Keep Test gently unavailable until capability discovery succeeds. Real device, transport, comfort and safety testing are still required. |
| Refine | The strongest task-focused screen: one expression curve, faint original, a visible local edit and undo. Pitch stays separate from bow weight. | Add time/beat scale, keyboard editing and accessible point selection. Define Original/Edit as audition controls, not merely a legend. Keep stop/panic ownership explicit. |
| Model | Reciprocal string/bridge/body diagram, six grouped controls, collapsed diagnostics and an honest synthetic-profile label. | Synthetic coefficients are not measured calibration. Only expose controls backed by the engine; independent loss/dispersion parameters need implementation and validation. Do not carry the identical knob settings into a meaningful default preset. |

## Boundaries

The images share an intentional paper/pine visual family, but independent image
generation does not enforce pixel-identical headers, icons, navigation or
spacing. Resolve those into one component library before implementation.
Do not treat notation in a generated picture as a valid score, curves as
recorded gestures, meters as measurements, or controller art as a hardware test.

Audition transport, loudness-matched A/B, continuous phrase editing/undo and
advanced DualSense feedback are still proposals. No engine, plugin or controller
code was changed by generating these images. The existing runnable studies and
native plugin keep their separately documented capabilities and limitations.
